🔄 Daily Git Sync

⎇ Git VS Code Terminal ⏰ Daily habit
⏰
When to use this

Run this at the start of every working day, before you create a PR, or any time you haven't synced in a few hours. On Salesforce projects, syncing often = fewer metadata conflicts. A 2-minute habit that prevents 2-hour headaches.

⚡ Quick Reference — Just the commands, in order 
# 1. See where you are
git status

# 2. Download everything from GitHub (safe — nothing changes yet)
git fetch origin

# 3. Update your local develop to match GitHub
git checkout develop
git pull origin develop

# 4. Go back to your feature branch
git checkout feature/your-story

# 5. Bring in the latest develop changes
git merge develop
#  — or, before a PR (cleaner history) —
git rebase develop

# 6. Confirm everything is up to date
git status
git log --oneline --graph --decorate -10
🧠 Mental Model — Git in 3 layers
Remote
GitHub origin/develop
↓
Local Base
your local develop
↓
Your Work
feature/your-story

Before doing anything meaningful: make sure Remote → Local Base → Your Work are all in sync. That's it. This workflow is how you do that.

Step-by-step walkthrough — click any step to expand
1
Verify which branch you're on ▾

Before touching anything, know where you are. It's easy to accidentally commit to develop or the wrong feature branch. This takes 2 seconds.

Run either of these
git branch git status
Git

You'll see a * next to your current branch — for example * feature/contract-amendment.

2
Fetch the latest changes from GitHub ▾

Think of this as: "Tell me everything that changed in GitHub." Nothing moves. Nothing breaks. It just downloads information so Git knows what exists on the remote.

git fetch origin
Git
3
Update your local develop branch ▾

Your teammates have been committing to develop all day. You need your local copy to match GitHub's version before you can merge from it.

Switch to develop
git checkout develop
Pull the latest
git pull origin develop
Git
✓ Your local develop now matches GitHub.
4
Switch back to your feature branch ▾

You updated develop — now go back to where your work lives so you can bring those updates in.

git checkout feature/your-story-name
Git

Replace your-story-name with your actual branch name. You can see it from Step 1.

5
Bring latest develop into your branch ▾

This is the key step — you're pulling your teammates' latest changes into your branch so you're working with the full, current codebase.

🤔 Decision point — Merge or Rebase?
Option A — Merge (most common)
git merge develop

Safe. Simple. Creates a merge commit. Hard to mess up. ✅ Use for your everyday sync.

Option B — Rebase (before a PR)
git rebase develop

Cleaner history. Your commits sit on top of the latest develop. ✅ Preferred right before opening a PR.

Git
6
Verify you are up to date ▾

Quick sanity check. You're looking for "Your branch is up to date." The graph command gives you a visual of recent commits.

Status check
git status
Visual commit graph (optional but useful)
git log --oneline --graph --decorate -10
Git
✓ You should see: Your branch is up to date with 'origin/develop'
📬 Before Creating a Pull Request — use this sequence
git fetch origin
git checkout develop
git pull origin develop
git checkout feature/my-story
git rebase develop
# Run your tests. Resolve any conflicts.
git push --force-with-lease
# --force-with-lease is safe. Only use it after a rebase.
⚠️
Watch out — Salesforce metadata conflicts

Apex classes, LWC files, permission sets, and flows conflict just like code — but they're harder to read. If you see CONFLICT (content): Merge conflict in AccountService.cls, open it in VS Code, fix the conflict markers, then run git add . → git commit (merge) or git add . → git rebase --continue (rebase). Sync often and these stay small.
